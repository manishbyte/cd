Select any practical assignment below to access complete source codes, lexical rules, grammar definitions, and execution logs.

Lexical Analysis

Practical 1: Lexical Analyzer for C Tokens

Constructs a complete lexical scanner in Flex that tokenizes C source code into headers, data types, identifiers, control keywords, relational/logical operators, comments, and bracket terminators.

Files: a.l • input.c
Tools: Flex • GCC • Ubuntu Terminal
Pattern Recognition

Practical 2: Lexical Analyzer for Number Systems

Disambiguates and classifies numerical representations including Binary (0b), Hexadecimal (0x), Octal (leading 0), Scientific Exponent (12e5), Signed Floats, and Integers.

Files: program2.l • input.txt
Tools: Flex • Regular Expressions • GCC
Parsing & Evaluation

Practical 3: Calculator using LEX and YACC

Implements an LALR(1) parser for evaluating arithmetic expressions supporting precedence, parentheses, unary minus, and runtime zero-division / modulo exception validation.

Files: calculator.l • calculator.y
Tools: Bison • Flex • GCC
Context-Free Grammar

Practical 4: CFG Language Validator (0ⁿ1ⁿ)

Defines grammar productions in Yacc to recognize and validate context-free language L = { 0ⁿ1ⁿ | n ≥ 1 }, ensuring balanced prefix 0s and suffix 1s with precise error detection.

Files: cfg.l • cfg.y
Tools: Bison • Flex • Grammar Automata
Code Generation

Practical 5: 8086 Assembly Code Generator

Synthesizes three-address and intermediate assignment statements into target Intel 8086 machine assembly instructions (MOV, ADD, SUB, MUL, DIV).

Files: exp.l • exp.y • input.txt
Tools: Lex • Yacc • Intel 8086 Assembly
Automata Theory

Practical 6: DFA for Decimal Divisibility by 3

Models a 3-state Deterministic Finite Automaton (DFA) using parser states (q0, q1, q2) to compute modulo 3 residue on streaming arbitrary decimal numbers.

Files: dfa.l • dfa.y
Tools: Bison • Lex • State Machine

2. Quick Command Summary

Reference cheat-sheet showing the compilation pipeline and execution commands for each practical inside its respective directory.

Practical Primary Source Files Terminal Compilation & Execution Pipeline
Practical 1 a.l, input.c flex a.l → gcc lex.yy.c -o a → ./a input.c

3. Troubleshooting & Diagnostics

Standard resolution table for compilation, linking, and runtime diagnostics encountered in Ubuntu Linux environment:

Observed Diagnostic / Message Root Cause & Prescribed Fix
flex: command not found or bison: command not found Packages missing from operating system. Install toolchain: sudo apt install -y flex bison build-essential.
fatal error: y.tab.h: No such file or directory Header file generation missing. Run Bison with -d flag before compiling Flex: bison -y -d file.y.
bash: ./calculator: No such file or directory GCC compilation did not produce executable due to prior compile error. Inspect terminal output from step 4 for fatal errors.
File read error: cannot open input.txt (Practical 5) The file input.txt is missing from the active directory. Create it in the current folder before launching ./exp.
Flex says unrecognized rule or bad character Rule pattern lines contain leading whitespace or invisible formatting characters. Re-paste the file ensuring pattern begins in column 1.
Program pauses and terminal appears unresponsive (Practicals 3, 4, 6) The interactive parser is awaiting user standard input (stdin). Enter your expression/number and press Enter (Ctrl + C to exit).
Compiler output displays warning: ... lines Warnings are non-fatal compiler notes. Only lines explicitly containing error: stop binary production.
Clean build / Reset workspace Purge generated compiler intermediate artifacts: rm -f lex.yy.c y.tab.c y.tab.h a.out
